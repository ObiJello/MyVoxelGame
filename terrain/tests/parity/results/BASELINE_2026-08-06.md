**Fixed (chunk (6,-2) 493 → 0, chunk (5,-6) 64 → 0, both now PERFECT):**
1. **`BlockState::isFaceSturdy` for sculk blocks** (THE sculk bug): veins were
   reported face-sturdy on faces they have set, but Java veins are noCollission
   → support shape empty → NEVER sturdy; sensor/shrieker are 16x8x16 bottom

   pops via `remove()`. Fixes oak/dark-oak (and likely spruce region) distance

3. `MultifaceSpreader` canSpreadInto now uses `isValidStateForPlacement` (vein
   already-has-face → try next SpreadType, matching Java fallthrough);

   early-returns before the `Direction.allShuffled` draw. (SculkSpreader.cpp)
4. `sculk_catalyst` now models `bloom` (default false) — `SculkCatalystBlockImpl`
   in Blocks.cpp.

**HARNESS BUG (fixed): the Java live-trace shadow logger wrote blocks.**

VegetationPatchFeature got its ground placed TWICE (shadow with cloned RNG,

**JavaHashSet now implements TREE BINS (red-black), ported 1:1 from OpenJDK
HashMap:** bins reaching 8 nodes treeify at table ≥64 (resize below),
untreeify at ≤6 on split/remove; treeified next-chains reorder via
moveRootToFront + insert-after-parent, changing iteration order vs plain
chains. This was the root cause of the surface-set iteration divergences in
`distributeVegetation` (short_grass/moss_carpet swaps) and residual big-tree
updateLeaves diffs — small sets never treeify, which is why single-chunk
repros were already perfect while r10 dark-forest chunks failed. BlockPos in
tree bins orders by spread hash only (comparableClassFor(BlockPos)==null in
Java because only Vec3i declares Comparable); exact 32-bit hash ties fall to
Java's identityHashCode (nondeterministic even in Java) — C++ uses dir=-1.
