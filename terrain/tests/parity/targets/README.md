# Java-only structure targets (Part B / plan "Structures + Nether + End")

Frozen Java ground truth for capabilities the C++ side does NOT implement yet.
Unlike `goldens/`, nothing here has ever been matched by C++ — these are the
dumps the structure port is aiming at. Once a capability lands and matches
fresh Java, real goldens get promoted through the normal `promote_goldens.sh`
flow and entries here become redundant.

- `java_s<seed>_r8_c0_0_p0-2.txt.gz` — canonical dumps at `--phases 0-2`
  (STRUCTURE_STARTS + REFERENCES): S/P/R record kinds per FORMAT.md.
  Generated by the Java harness, byte-deterministic (double-run verified
  2026-08-08).
- `java_placements_s<seed>_c0_0_r64.txt.gz` — `--trace-placements` sidecar:
  POSSIBLE (biome-filtered structure-set list in createStructures iteration
  order), RING (concentric-ring stronghold positions), PS (isStructureChunk
  hits over a radius-64 chunk scan). Pure placement layer, no chunk generation
  — the B1 gate compares the C++ placement port against these with plain diff.

Regenerate:
```
./run_minecraft_async_test.sh --radius 8 --center 0 0 --phases 0-2 --seed <S> \
    --dump-full --output <dump> \
    --trace-placements <trace> --placement-radius 64 --quiet
```
